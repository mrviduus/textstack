A distributed database has to survive a network partition without giving up linearizability. Most designs elect a leader with a consensus algorithm such as Raft, which needs a quorum of nodes to agree. Each leader gets a monotonically increasing term number, and every write is appended to a write-ahead log before it is acknowledged. If an old leader wakes up holding a stale lease, a fencing token stops it from corrupting storage. Reads that tolerate staleness can go to followers; the rest pay a round trip to the leader, and idempotent retries keep the client safe when a request times out.
