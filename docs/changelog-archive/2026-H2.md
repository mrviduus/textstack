## Word translation without its sentence; PDF page count — mobile, web, backend, shared, evals — 2026-10-08

**Translation.** QA-007 saw "pocketed" → "enterrado" (pt-BR, *buried*). The server prompt
(`TranslatePrompt`) uses "Sentence context", and web's word bubble sent it — but every mobile caller
went through `translateCache.cachedTranslate` → `translationApi.translate(text, from, to)`, which posted
the bare word, and the cache key had no sentence either. So every tapped word on the phone was
translated out of context. Now the shared `translate` takes `{ sentence, bookId }` (pure
`translateBody`, tested), mobile passes the selection's sentence and keys its cache by it, and the two
web paths that also sent nothing (selection toolbar, language-switch refetch) do too.

Review follow-up: mobile's Translate sheet and save path now send the same `{ sentence, bookId }` as
the toolbar (bookId = editionId or userBookId, as web sends; `ResolveGenreAsync` takes either), so they
hit its cache entry; the client key includes bookId as the server's includes genre. The gloss backfill
(web and mobile) translates a word in the sentence it was saved in (sentence only, no bookId) —
`GET /me/vocabulary/words/reader?includeSentences=true` returns `sentence` (capped at 300 chars) for a
word with no translation; the clients ask for it only when translating into another language, so
definition mode and the plain list stay light. (The bubble's guard against writing another sentence's
sense onto a saved word was replaced in the seventh round by no write at all.)

Third review round: `translateBody` (shared, now also what web's `translate` posts) sends the sentence
only for a word or a phrase of up to 3 words that is not the sentence itself — a passage is its own
context. Web's sentence extractor finds the tapped occurrence by its range offset, not the first
`indexOf` match ("The wound bled. Later she wound the clock."). Web's IndexedDB translation key adds
bookId (calls without one keep their old key). Mobile keeps the saved sentence in its vocab map entry,
but `vocabPaintJs` injects only `{ stage, translation }` — what `markVocabWords` reads.

Fourth round — simpler plumbing. The main reader-vocab load is back to once per auth state with no
sentences: making it depend on the native language refetched and *replaced* the map on a language
change, wiping pending/just-saved words. The gloss backfill (rare: untranslated words, target ≠ book
language) now fetches its own `?includeSentences=true` list right before it runs, sends
`{ sentence, bookId }`, and is marked done only once it ran with that data (a failed fetch retries).
One client cache-key rule, `translateCacheKey` (shared, next to `translateBody`), derived from the
body actually sent — mobile's memory cache and web's IndexedDB key both use it, so a passage's dropped
sentence is not in its key. Mobile's save gloss uses the toolbar's sentence (the selection's, not the
server's echo), so it is the toolbar's cache hit. The page-count CLI also
selects Failed PDF uploads (`PdfPageCountBackfill.NeedsPageCount`).

Fifth round — one fetch. `?includeSentences` is gone: `GET /me/vocabulary/words/reader` always returns
`sentence` for an untranslated word only, as a ~200-char window centred on the word (`SentenceWindow`;
the start if the word is absent) instead of the first 300 chars. The backfill (web and mobile, same
filter: skip words removed, pending or translated since) uses the main load's sentences — no second
fetch, no idle/running/done state — and on mobile is cancelled on unmount, sign-out, account, book or
language change (not on its own per-word repaint). Ceiling: definition-mode readers have no
translations, so every word ships its window. `translateCacheKey` keeps the text's case ("US" ≠ "us")
and is a JSON array; web's IndexedDB stores that full string as the key instead of a 32-bit hash, so a
collision cannot serve another entry (old hashed rows age out in 7 days). Mobile's vocab map entry
dropped `sentence` — nothing read it.

Sixth round. The gloss backfill (web and mobile) sends `{ sentence }` only, no bookId: the saved
sentence may come from another book, and the open one's genre would bias a translation that is then
written for good. Web and mobile skip and write per server row, so "Turkey" and "turkey" each get their own.
`SentenceWindow` cuts at word boundaries and never inside a surrogate pair. `translateBody` sends the
trimmed sentence, the same one `translateCacheKey` keys. The page-count CLI projects only id + path and
writes each book as it goes (`PdfPageCountBackfill.RunAsync`): one failure is logged and skipped, the
rest kept. Mobile derives `translateBookId` once, in `ReaderShell`. Accepted ceilings: old web
IndexedDB translation rows miss once after deploy (they age out within 7 days). Cache rows are per
word + sentence by design. A word saved this session whose translate failed is backfilled on the next
reader load.

Seventh round — delete, not guard. **The word bubble never persists a translation onto a saved word.**
A saved word's translation is written at save time (with its sentence) and by the gloss backfill (with
its sentence), nowhere else. `mayWriteSavedTranslation` and `savedTranslation.ts` are deleted, and so are
the bubble's writes on open (`fetchWordBubble`) and on a language switch (`useBubbleTranslationSync`) —
the bubble still shows its own translation. The one remaining bubble write is save time: auto-save fires
as the bubble opens, before its translation arrives, so that translation is written once onto the word
that bubble just saved, if it has none. Mobile never had such a write. `translateBody` also caps a
"short text" at 40 characters, so a passage in a script without spaces is not one "word". The PDF
extractor returns the page count when the document opened and extraction failed later, and ingestion
never overwrites a stored page count with none. `SentenceWindow` finds the word on word boundaries
first ("art" not in "Start"). Web's book JSON-LD uses the shared `bookPages`. Accepted ceilings: the
gloss backfill covers words from the main load only; definition-mode readers ship a sentence window
for every word.
