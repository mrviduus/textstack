# Reader engine — rules

What `packages/reader-engine` promises its hosts (web, mobile), in plain words. Design and API:
[ADR-025](../01-architecture/adr/ADR-025-reader-engine-package.md); position rules:
[ADR-019](../01-architecture/adr/ADR-019-reader-position-rules.md); slices:
[phase 2 plan](../01-architecture/reader-engine-phase2-plan.md).

Each rule has one ID. The test that pins it starts its name with that ID
(`packages/reader-engine/src/engine.test.ts`; decorations, E13–E19, E44, E49–E51 and E54, in `decorations.test.ts`; events, E20–E24 and E28, in `events.test.ts`; geometry on real chapters in Chromium, E25–E27, E29, E30, E43 and E45, in `playground/geometry.e2e.ts`). Change a rule here first, then its test, then the code.

ADR-019's eight position rules are pinned once each in `src/positionRules.test.ts` (`rule 1` … `rule 8`),
through the engine and the pure rules it re-exports from shared (`newerPosition`, `progressPrecedence`,
`pdfPersistGate`; the code moves in Phase 6). With the engine, "the reader moved" = a `'scroll'` arrived:
no pixel tolerance, so `readerMovedSince` is not re-exported. Rule 6 in the engine: a webfont that never
loads holds an `open` 4 s at most.

**Words used below.** The *reading line* is a quarter down the screen: the text there is "where the
reader is". An *op* is `open`, `goTo` or `setStyle`. An op's *ack* is the one `relocated` event that
carries its `opId`.

## Rules (owner-decided)

| ID | Rule | Why / source | Since |
|---|---|---|---|
| E1 | `open` shows the chapter, says `ready`, then acks once — before its promise resolves. | ADR-025 API rule; replaces the mobile restore ack (ADR-019 rule 3) | 2026-10-12 |
| E2 | A saved position (open or goTo) puts its sentence on the reading line. A position with only a fraction lands on that fraction of the chapter itself (not the host's footer or padding), the `chapterFraction` the apps store. | ADR-015: position = place in the text | 2026-10-12 |
| E3 | A position from another chapter never moves to a look-alike place. `goTo`: no move, `anchor-miss` error naming the chapter, resolves `'superseded'` (not landed). `open`: opens at the top, `'start'`, same error. | Owner decision D1; ADR-015 | 2026-10-12 |
| E4 | A newer `open` / `goTo` supersedes an older one: the older resolves `'superseded'`. Every op is still acked exactly once. | ADR-019 rule 3: a stale restore lands nothing | 2026-10-12 |
| E5 | Only the reader scrolling, after the last op finished, is `'scroll'` (reading). The engine's own scrolls never are; a scroll during an op is ignored. | ADR-019 rule 7; web `wordsRead` ≈ 0, mobile M8 | 2026-10-12 |
| E6 | A style change (font size, …) keeps the same sentence on the reading line and never rebuilds the chapter. Two quick changes keep the first place. | ADR-025; R2 font-change re-anchor | 2026-10-12 |
| E7 | A style change during a restore keeps the restore target. While an op runs, "where the reader is" is its target, never the half-moved view. | ADR-019 rule 8; mobile "rebuild mid-restore saves 0" | 2026-10-12 |
| E8 | When the chapter changes size late (an image or webfont loads), the same sentence stays on the reading line, with one `'reflow'` event. No size change → no event. | ADR-025 "re-anchor on late image loads" | 2026-10-12 |
| E9 | `destroy` stops every event and empties the container, and gives it back as it was; a running op resolves `'superseded'`. | ADR-025 API | 2026-10-12 |
| E10 | Real server HTML (newlines between blocks, blocks inside blocks) behaves the same as clean HTML. | Code review of slice 3 (bug: all positions below paragraph 1 read as one) | 2026-10-12 |
| E11 | An op's ack names the place it was sent to, even when the scroll stops short (chapter top or end). | Code review of slice 3 (bug: position moved backwards on save) | 2026-10-12 |
| E12 | `ready` fires for every chapter shown, even when a `goTo` overtakes the `open`. | Code review of slice 3 (bug: host waits forever) | 2026-10-12 |
| E13 | `decorate` draws each highlight or search hit over its text; the chapter's text nodes never change. A call replaces its own group only. A box with no area (a line end, a column edge) is not drawn. | ADR-025: decorations draw over the text | 2026-10-12 |
| E14 | An item from another chapter, or whose text is gone, is not drawn. Never on a look-alike place. | ADR-015; same ladder as `goTo` (quote, exact or fuzzy) | 2026-10-12 |
| E15 | Decorations follow their text: redrawn after a style change and a late reflow. They belong to their chapter: open another and its own are drawn; come back and these are again. | Web R2 "ghost highlights" / new chapter never painted | 2026-10-12 |
| E16 | A tap on a highlight or search hit emits `decorationTap` with its id and box on screen. A highlight under a search hit wins. A tap on plain text, or the click that ends a selection, emits nothing. | ADR-025 API | 2026-10-12 |
| E17 | `find` returns every match in reading order (any case, a no-break space = a space), each with 40 characters of context and a locator `goTo` and `decorate` land on. | Web in-book search (drawer list = painted hits) | 2026-10-12 |
| E18 | `markWords` underlines each saved word where it stands as a whole word, in any case; a block or a footnote ends a word. A saved phrase is marked whole, never also as its words. A call replaces the set. | Web vocab matcher, now over the chapter text | 2026-10-12 |
| E19 | With translations on, each marked word with a translation shows it above the word, drawn over the text: the chapter text, and so every anchor and position, stays the same. | STATUS "legacy `<mark>` vocab path": the root fix | 2026-10-12 |
| E20 | A drag selection in the chapter, once it stops changing (220 ms), emits `selection` (`source:'drag'`): its text, its sentence, a locator `goTo` and `decorate` land on and its box on screen. Over 500 characters it is still sent, with `tooLong`. A drag running on past the chapter is its part in the chapter; the same text is never sent twice. When it goes away, or another `open` replaces it: `null`. | Mobile bridge: iOS fires `selectionchange` mid-drag; server translate/TTS cap 500 | 2026-10-12 |
| E21 | A finger held still 450 ms on a word emits `hold`, then a `selection` of the whole word (soft hyphens and `’` inside it; `source:'hold'`), marked over the text; the page's own selection is never touched (Android would open its menu). Moving 8 px cancels; a hold on a link does nothing. `clearSelection` removes the mark. | Mobile word hold; SEL-1 (the mark stays while the toolbar is open) | 2026-10-12 |
| E22 | A tap emits one event: an image `imageTap` (also inside a link; `src` is the source the browser chose from `srcset`), a link `linkClick` (relative = `internal`; the page never navigates), a highlight or search hit `decorationTap` (E16), else `tap`. The click that ends a selection or a hold, and a tap on the footer, emit nothing. | ADR-025 events; the mobile lightbox opens an image inside a link (fixed 2026-10-12: this rule said the reverse) | 2026-10-12 |
| E23 | Reader scrolling emits `scrollDir` when the direction changes: `'down'` after 48 px, `'up'` after 6 px (hide the bars late, show them early). The engine's own scrolls never do. | Mobile scroll-direction detector | 2026-10-12 |
| E24 | `setFooter` puts the host's block after the chapter, in the scroll flow but outside its text (positions, `find`, decorations unchanged). `chapterEnd` fires once per open, when the footer comes into view: by scrolling, an op, a style change or a reflow. | ADR-025: chapter-end block contents stay the host's | 2026-10-12 |
| E25 | In a browser the engine reads the reading line with the caret, like the apps: its place is on the line web's caret probe reads. Like the apps it takes a caret on text only (an empty table cell is skipped, #802). With no caret API it estimates per block. | [#789](https://github.com/mrviduus/textstack/issues/789): the old estimate was off by up to 226 px | 2026-10-12 |
| E26 | `goTo` puts the place's line on the reading line, also when the place starts on a soft hyphen or whitespace (no width). Until the reader scrolls, `current()` is that place exactly: open and save without a scroll never drifts. | #789; ADR-015 | 2026-10-12 |
| E27 | Reading the place on a reader scroll costs under 4 ms a frame (a quarter of one at 60 fps) on a long chapter (Ulysses XV, 2760 table cells), CPU 4× slower. | [#790](https://github.com/mrviduus/textstack/issues/790): 6.3 ms before, 0.4 ms with the caret, 0.1 ms with element carets skipped ([#804](https://github.com/mrviduus/textstack/issues/804)) | 2026-10-12 |
| E28 | A tap of any kind (text, link, image, highlight) within 300 ms of the last one is a double (or triple) tap and emits nothing (a link still never navigates): the bars toggle once. The first tap is sent at once, never held. A clock change does not matter. | [#799](https://github.com/mrviduus/textstack/issues/799), owner choice; the old bridge held every tap 300 ms | 2026-10-12 |
| E29 | The chapter growing above the reading line (an image loads) is one `'reflow'`, never `'scroll'`: the engine alone re-anchors (browser scroll anchoring is off in the chapter). | [#794](https://github.com/mrviduus/textstack/issues/794): Chromium anchors at once (+300 px) and only frame order kept its scroll from reading as the reader | 2026-10-12 |
| E30 | A style change is one `'style'` relocation: the browser never scrolls the page before the engine re-anchors (scroll anchoring is off on the scroller, not only in the chapter). | Phase 4 slice 1: with only the text excluded, Chromium anchored on the decoration layer (~3 px), and web saved that scroll as the reader's | 2026-10-12 |
| E31 | A decoration with the style `'dot'` draws a small dot just after its last line, no fill; a tap on its text still names it (E16). | Web reviewed highlight (`reviewed-mark`), Phase 4 decision 2 | 2026-10-13 |
| E43 | A style change while something covers the reading line (web's settings drawer) keeps the same place. With no scroll since the last place was reported, that place is the anchor (rule 8), so nothing is read under the cover; any reading under a cover goes by line-box geometry, with no text on the line meaning the nearest text above (E45). Pinned in `playground/geometry.e2e.ts`. | H2b (old web reader: font change under the drawer) | 2026-10-14 |
| E44 | A translation label carries its own look (0.42em, italic, weight 400, opacity 0.55; the chapter's own font, not a system one) as one inline `style`: no host CSS needed, and a bold chapter never leaks in. | Web lacked the host rule for a while: labels drew at body size in prod | 2026-10-14 |
| E45 | Something over the reading line (a drawer, a popup) never hides the reader's place: when the caret there lands outside every engine's text, the engine finds the text on the reading line by the text's own line boxes (no hit test; floated figures and their captions too; a line with no text on it, beside or on a picture or in a gap between blocks, is the text ending nearest above it, so on return the text just read sits on the line with the picture below it (owner)), with a bounded search (hidden text, word joiners and whitespace runs of any length are stepped over), so every scroll under it reports the text truly on the line, and a style change under it keeps that text. A caret on another engine's chapter (`data-reader-engine` on its root) is no cover. | H2b follow-up (owner: no known gaps): a scroll behind the drawer read the estimate; #852 review: keeping the stale place under a word popup would save it | 2026-10-14 |
| E46 | `open` resolves `'superseded'` in two cases a host can tell apart: its document was replaced (a newer `open`, `destroy`: `current()` is another chapter or null), or a `goTo` overtook it after its document landed (`ready` was said and `current().href` is this chapter). In the second case the chapter is open and positioned by the `goTo`: a host may treat it as opened. | #852 review: web left a chapter un-ready when a `goTo` overtook its open | 2026-10-14 |
| E47 | `clearSelection({ markOnly: true })` removes only the held word's mark: the page's own selection stays and nothing is sent (no `selection: null`). The host calls it right before it paints that text as a highlight, so a failed save leaves the selection for another try. Plain `clearSelection()` still ends everything. Reflow and PDF. | SEL-1 (old bridge `markOnly`): the engine page ignored it, so a failed highlight dropped the selection | 2026-10-15 |
| E48 | A selection's sentence is the one the shared TR-1 fixture (`packages/shared/src/text/__fixtures__/sentences.json`) pins: the tapped occurrence's own sentence, ended by `.`, `!` or `?`, never a gloss; a long one is cut to 200 characters around the word, and a cut edge keeps its space (`... words`). | TR-1 (translate sent the wrong sentence); the old web and mobile extractors shared this fixture | 2026-10-15 |
| E49 | `find` matches a composed letter and its decomposed form (`é` = `e` + U+0301) either way round: query and text are NFC-normalised the same way, as saved words are (E18). | Review of #868: search folded case and NBSP but not NFC | 2026-10-15 |
| E50 | A `find` hit is quoted at its own place in the chapter's text even after a letter whose fold changes length (Turkish `İ` lowercases to two characters): offsets are mapped back from the folded text. | Review of #868: `find` used `at + query.length` on folded offsets | 2026-10-15 |
| E51 | `find` and `markWords` fold the same way: a dotted capital `İ` matches a plain `i` (`istanbul` finds `İstanbul`), and a saved word or phrase after a letter whose fold changes length (`İ`, `e` + U+0301) is marked on its own letters. | [#869](https://github.com/mrviduus/textstack/issues/869): `matchWords` used folded offsets on the text as written | 2026-10-15 |
| E54 | A translation label's baseline sits just above its word's glyphs (the letters' top, measured on a canvas in the chapter's font), not above the line box. The box is the font's ascent + descent (TextStack 1.56em vs Georgia 1.14em), so anchoring to its top floated labels over the line above. No metrics → the box top, as before. | After the TextStack font (#885) labels floated high and overlapped the line above | 2026-10-16 |

### Fixed layout (PDF, Phase 5)

Pinned in `src/fixed.test.ts` (jsdom, a fake pdf.js) and `playground/fixed.e2e.ts` (Chromium, the committed fixture).
The generic rules hold for a PDF too and are pinned there under their own IDs (E4 supersede, E6 style ack, E7 `current()` mid-op, E9 destroy, E12 ready; E20 drag selection, E21 hold, E22 tap, E23 scroll direction, E28 double tap).
A PDF's place is its page: `locations.position`, 1-based (stored as `page:<N>`, frozen).

| ID | Rule | Why / source | Since |
|---|---|---|---|
| E32 | The host brings pdf.js: `createEngine(root, { fixed: fixedLayout(pdfjs) })`; the engine never imports it. Such an engine opens PDFs (`layout:'fixed'`); one without it throws on a PDF. `open` shows one box per page, each its own shape, fit to the width, says `ready` with `pageCount`, then acks once with the page. | Phase 5 answer 3a: 64 KB budget, pdf.js ~1.8 MB | 2026-10-13 |
| E33 | A page (open or `goTo`) puts that page's top at the top of the screen, once the sizes of every page above it are known (they stream in), and acks with that page. Out of range: the nearest page (never page 0). No page: page 1, `'start'`. Sizes that never come: it lands on the estimate after 8 s. | Mobile viewer: a jump landed on estimated heights, every reopen drifted | 2026-10-13 |
| E34 | Bytes come from the host only: `pdf.data`, or `pdf.read(begin, end)` by ranges (pdf.js range transport: first paint before the whole file). A `read` rejected with `{ code: 'pdf-auth' }` is one `'pdf-auth'` error; any other failure to load is `'pdf-load'`. A failed open still acks, with the page it was sent to, and resolves `'superseded'`. | Phase 5 answer 4a; ADR-025 "PDF bytes come through `read()`" | 2026-10-13 |
| E35 | Only pages near the screen have a canvas: drawn within one page of the visible ones (300 px margin), freed past two (shared `computePageRings`); the count stays bounded however far the reader goes. | A 100-page PDF without the window ran the tab out of memory | 2026-10-13 |
| E36 | The reader scrolling to another page emits one `'scroll'` with it (the page filling most of the screen, shared `readingPage`); the engine's own scrolls never do. The reader's gesture (touch, wheel, a scroll key: arrows, PageUp / PageDown, Space, Home / End; not Escape or a modifier), or any scroll the engine did not make (a scrollbar drag, middle-click autoscroll, #829), during a jump ends it where they are: it resolves `'superseded'`, acked with that page, and never snaps back. | QA-007 #3 (save the page being read); mobile "TOC jump cancelled by a drag"; [#829](https://github.com/mrviduus/textstack/issues/829) (2026-10-15) | 2026-10-13 |
| E37 | Sizes arriving and a re-fit (the width changes) keep the reader on the same spot of the same page. While the reader scrolls (a fling), the change waits until scrolling has stopped 150 ms: a scroll from code stops a fling. | Mobile viewer: +3 pages per reopen after a late re-fit | 2026-10-13 |
| E38 | `setStyle({ zoom })` scales every page to fit × zoom (0.2–5×; `'fit'` = 1), redraws the drawn pages sharp at the new scale and keeps the page under the top line at the same fraction (the shared zoom anchor, web H4); one `'style'` ack with that page. A zoom is the reader's command: it never waits for a fling. A page wider than the screen scrolls sideways, never cut off on the left. | Phase 5 answer 5a (web zoom buttons); web H4 | 2026-10-14 |
| E39 | Each drawn page has pdf.js's text layer over its canvas, at the page's scale: the text can be selected. It goes with the canvas when the page leaves the window. | ADR-012 original-first: select, translate, highlight on the scan | 2026-10-14 |
| E40 | A selection on a PDF (drag or hold) carries a locator with its page, its text (`text.highlight`) and its rects (`ext.rects`, page-relative at scale 1), so `locatorToPdfAnchor` writes today's `PdfAnchor` and the stored highlight paints back on the same text at any zoom. A selection that runs onto the next page keeps the start page's part. | Stored `PdfAnchor` is frozen (ADR-025); web/mobile `buildPdfAnchor` | 2026-10-14 |
| E41 | `decorate` paints each item on its page from its `ext.rects` at the live scale (a `'dot'`: a dot just after the last rect), over the text but letting a selection start through it; repainted after a zoom; a call replaces its group. A tap on a painted rect emits `decorationTap` (by geometry; a highlight wins over a search hit). An item with no page or no rects is not drawn. | Web `PdfHighlightLayer` + M2 hit test; mobile `__pdfHighlightAtPoint` | 2026-10-14 |
| E42 | On a PDF, `setStyle({ insets })` sets where a page lands: an open or `goTo` (a resume, a TOC jump) puts the page's top `insets.top` below the top of the screen, clear of the host's fixed bars, never scrolled above 0. It moves nothing by itself; a size change or a zoom keeps the reader's spot on that line, not on the line under the bars (E37, E38). | Phase 5 slice 3 review: web jumps landed under the top bar and the toolbar | 2026-10-14 |
